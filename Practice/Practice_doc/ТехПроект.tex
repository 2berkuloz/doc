\section{Технический проект}
\subsection{Общая характеристика организации решения задачи}

Разрабатывается клиентская сторона веб-приложения для чат-платформы, обеспечивающая взаимодействие пользователя с серверной частью программы и базой данных. Клиентская сторона реализует следующие основные функции:
\begin{itemize}
	\item аутентификация и авторизация пользователей;
	\item обмен сообщениями в групповых чатах;
	\item личная переписка между пользователями;
	\item управление группами и правами участников;
	\item работа с вложениями и медиафайлами.
\end{itemize}

\subsection{Обоснование выбора технологии проектирования}  
\subsubsection{Язык программирования JavaScript}  

JavaScript выбран из-за его уникальной способности работать напрямую в браузере. Это позволяет пользователям открывать мессенджер на любом устройстве — от смартфона до компьютера — без установки дополнительных программ.  

Основное преимущество — полный контроль над кодом. Отказ от библиотек упростил безопасность: нет риска уязвимостей из-за сторонних компонентов. Например, проверка логинов и паролей в модулях входа и регистрации использует только встроенные функции браузера, что исключает утечки данных.  

Работа в реальном времени обеспечена технологией для мгновенной передачи сообщений, которая встроена в браузеры. Пользователи видят новые сообщения без задержек, даже когда в чате много участников. История переписки сохраняется во встроенном хранилище браузера — если случайно закрыть вкладку, все данные восстановятся.  

Разработка упрощена благодаря гибкости языка. Добавление новых функций, вроде выбора смайликов или отправки файлов, требует минимального кода. Например, при отправке файла JavaScript сразу показывает его миниатюру, проверяет размер и тип, а затем отправляет на сервер — всё это работает без плагинов.  

Сравнение с другими технологиями показывает их избыточность для этой задачи. TypeScript требует дополнительных шагов перед запуском, что замедляет процесс. WebAssembly полезен только для сложных вычислений вроде шифрования, а для интерфейса не нужен. Популярные фреймворки вроде React добавляют лишние слои кода, усложняя поиск ошибок.  

Проект доказывает, что чистый JavaScript подходит для создания сложных приложений. Все функции — от аутентификации до групповых чатов — реализованы на базовых возможностях языка, что обеспечивает стабильность и простоту поддержки.  

\subsubsection{Язык программирования CSS}

CSS выбран как основной инструмент стилизации благодаря следующим преимуществам:

Преимущества использования чистого CSS:
\begin{itemize}
	\item лёгковесность — стили загружаются отдельно от HTML-структуры;
	\item мгновенная интерпретация браузером без этапа компиляции;
	\item полная поддержка всеми современными веб-обозревателями;
	\item простота отладки через встроенные инструменты разработчика.
\end{itemize}

Ключевые особенности реализации:
\begin{enumerate}
	\item Адаптивный дизайн. Медиа-запросы (@media (max-width: 768px)) обеспечивают корректное отображение на мобильных устройствах за счёт динамического изменения сетки макета и размеров элементов.
	
	\item Производительность. Использование аппаратного ускорения для анимаций (transform, opacity) снижает нагрузку на процессор, а техника ленивой загрузки стилей уменьшает время первоначальной отрисовки страницы.
	
	\item Совместимость. Постепенное улучшение через feature queries гарантирует работу основных функций в старых браузерах, а автопрефиксация критических свойств обеспечивает кросс-платформенность.
\end{enumerate}

Примеры практической реализации:
\begin{itemize}
	\item плавные переходы для интерактивных элементов: transition: all 0.3s ease;
	\item динамические тени при наведении: box-shadow: 0 5px 15px rgba(0,0,0,0.1);
	\item сложные фоновые градиенты: linear-gradient(135deg, \#FFDAB9 0\%, \#FFB6C1 100\%);
	\item кастомные скроллбары через псевдоэлемент ::-webkit-scrollbar.
\end{itemize}

\subsection{Общая характеристика организации решения задачи}

Боковое меню «Мои группы» реализует функционал управления групповыми чатами и обеспечивает навигацию между ними. Основные компоненты и механизмы работы меню включают:

\begin{itemize}
	\item динамическую загрузку списка групп через AJAX-запросы к серверу с использованием метода loadGroups();
	\item визуализацию групп в DOM-элементе groups-list с отображением названия, статуса активности и контекстного меню управления;
	\item обработку событий выбора группы через функцию selectGroup(), которая обновляет интерфейс чата и сохраняет состояние в sessionStorage;
	\item систему проверки прав доступа к группам через эндпоинт /checkgroupaccess перед отображением содержимого чата;
	\item контекстное меню управления группой с возможностями: переименование через renameGroupPrompt(), добавление участников через addMemberPrompt(), выход из группы через leaveGroupPrompt();
	\item механизм создания новых групп через модальное окно с валидацией ввода и отправкой данных методом createGroup();
	\item синхронизацию состояния интерфейса с сервером посредством периодического вызова checkGroupsUpdates();
	\item обработку навигации между общим чатом и групповыми чатами через систему хранения текущего состояния в currentGroup.
\end{itemize}

Модуль взаимодействует с серверной частью через REST API, используя методы GET для получения данных и POST/PATCH/DELETE для модификации. Состояние интерфейса автоматически обновляется при изменениях через систему обратных вызовов и событийную модель браузера.

Ключевые особенности реализации:  
\begin{enumerate}
	\item Адаптивная структура. Медиа-запросы в сочетании с гибкими единицами измерения (vw, \%) обеспечивают автоматическое изменение макета для мобильных устройств. Зоны header и sidebar адаптируются под размер экрана через CSS Grid.
	
	\item Динамическое содержимое. Генерация элементов интерфейса (сообщений, списка групп, участников) осуществляется через JavaScript с использованием шаблонов template. Это снижает нагрузку на сервер при первоначальной загрузке страницы.
	
	\item Валидация данных. Комбинация HTML5-атрибутов (required, pattern) с кастомной JavaScript-проверкой обеспечивает двойной контроль вводимых данных. Для полей логина и пароля реализована проверка сложности символов.
\end{enumerate}

Примеры технических решений:  
\begin{itemize}
	\item разделение интерфейса на три независимые зоны: header для управления, sidebar для навигации, main для контента;
	\item использование тега audio для воспроизведения звуковых уведомлений;
	\item реализация модальных окон через div с фиксированным позиционированием;
	\item оптимизация загрузки ресурсов через атрибуты defer и async.
\end{itemize}

\subsection{Пример реализация бокового меню Мои группы}

Боковое меню "Мои группы" обеспечивает управление групповыми чатами и правами участников. Реализация функционала включает следующие компоненты:

\begin{enumerate}
	\item Динамическая загрузка списка групп. Функция loadGroups отправляет GET-запрос к эндпоинту {/get\_groups}, обрабатывает ответ сервера и рендерит элементы интерфейса. При обновлении сохраняется позиция прокрутки, а активная группа выделяется визуально с помощью класса active.
	
	\item Создание групп через модальный диалог. Обработчик createGroup инициирует prompt-окно для ввода названия, валидирует длину строки и отправляет POST-запрос на /create\_group. Успешный ответ триггерит повторную загрузку списка и анимацию добавления новой группы.
	
	\item Механизм переключения между чатами. Функция selectGroup обновляет заголовок текущего чата, сохраняет состояние в sessionStorage, проверяет права доступа через /check\_group\_access и инициирует загрузку сообщений через loadMessages.
	
	\item Контекстное управление группами. Меню toggleGroupMenu предоставляет опции переименования, добавления участников и выхода из группы. Для изменения названия используется fetch-запрос к /rename\_group с последующим обновлением DOM.
	
	\item Фоновая синхронизация данных. Метод checkInterfaceUpdates периодически проверяет изменения через /check\_groups\_updates, обновляя список групп при модификациях другими пользователями.
\end{enumerate}

Архитектура модуля использует REST API для взаимодействия с сервером и sessionStorage для сохранения состояния интерфейса. Визуальные элементы реализованы через CSS-анимации трансформаций и теневых эффектов для плавности взаимодействия.

\subsection{Ключевые функциональные модули}

\subsubsection{Управление интерфейсом}
Система взаимодействия с пользователем реализуется через initUI(), инициализирующую все элементы при загрузке страницы. toggleSidebar() управляет видимостью боковых панелей, синхронизируя их состояние с SessionStorage. Динамическое обновление блока авторизации (updateAuthButtons()) отражает изменения статуса пользователя, а унифицированная система уведомлений (showToast()) использует анимированные всплывающие сообщения с цветовой индикацией типа события.

\subsubsection{Обработка сообщений}
Механизм работы с сообщениями включает цепочку операций: sendMessage() обрабатывает ввод данных с валидацией содержимого, loadMessages() загружает историю через API с пагинацией, а displayMessages() оптимизирует рендеринг через виртуальный скролл. Редактирование реализовано через enableMessageEditing() с автоматическим сохранением версий, а deleteMessageById() обеспечивает мягкое удаление с архивированием.

\subsubsection{Управление коммуникациями}
	Работа с группами основана на loadGroups(), кэширующем список чатов при первом обращении. selectGroup() активирует выбранное пространство, подгружая участников через loadParticipants() с дебаунсингом запросов. Для личной переписки selectPrivateChat() инициирует защищенный канал, проверяя права доступа перед созданием сессии.
	
	\subsubsection{Работа с файлами}
		Система вложений использует updateFileIndicator() для отображения процесса загрузки, showPreviews() генерирует миниатюры изображений и иконки файлов. clearFiles() реализует отмену выбора с отзывом blob-объектов, а downloadAllAttachments() пакетирует файлы в zip-архив через Streams API.
		
\subsection{Управление состоянием}  
Архитектура управления состоянием обеспечивает целостность данных при переходе между страницами и перезагрузках. Трехуровневая система сочетает краткосрочное хранение сессионных данных с реактивным обновлением интерфейса:  

\begin{itemize}  
	\item sessionStorage сохраняет учётные данные и активный контекст чата;  
	\item глобальные переменные отслеживают текущую группу (currentGroup) и приватную беседу (currentPrivateChat);  
	\item UI-состояние (открытые панели, модальные окна) управляется через наблюдаемые свойства DOM.  
\end{itemize}  

\subsection{Механизмы синхронизации}  
Для минимизации задержек при обновлении данных реализована гибридная модель, сочетающая клиент-серверное взаимодействие:  

\begin{itemize}  
	\item фоновый опрос через checkForUpdates() (интервал 2.5 сек);  
	\item событийные триггеры на действия пользователя;  
	\item дебаунс-обёртки (debouncedUpdate()) для ресурсоёмких операций.  
\end{itemize}  

\subsection{Оптимизация и безопасность}  
Многоуровневый подход к защите и производительности обеспечивает стабильную работу системы под нагрузкой:  

\begin{itemize}  
	\item санитизация HTML через DOMPurify;  
	\item валидация полей ввода регулярными выражениями;  
	\item шифрование локальных данных с помощью Web Crypto API;  
	\item автоматический выход при невалидных токенах.  
\end{itemize}

Принципы отзывчивого дизайна реализованы через адаптацию контента к различным устройствам:

\subsection{Обработка сбоев}  
Комплексная система восстановления после ошибок снижает влияние сбоев на пользовательский опыт:  

\begin{itemize}  
	\item перехватчики Fetch-запросов;  
	\item визуальные индикаторы с таймаутом;  
	\item экспоненциальную задержку повторов;  
	\item интеграцию с Sentry для критичных сбоев.  
\end{itemize}
