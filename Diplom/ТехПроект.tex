\section{Технический проект}
\subsection{Общая характеристика организации решения задачи}

Необходимо разработать концепцию пользовательского интерфейса для закрытого корпоративного мессенджера, который будет спроектирован как единое, адаптивное, кроссплатформенное веб-приложение, обеспечивающий комфортную работу на различных устройствах (компьютеры, планшеты, мобильные телефоны). В его основе лежит четкая структура и логика, призванная упростить доступ к ключевым функциям.

\begin{enumerate}
	\item Регистрация и авторизация пользователя путем идентификатора (логин) и аутентификатора (пароль) на страницах register и login.
	\item Возможность создавать групповые чаты.
	\item Возможность вести личный чат с другими пользователями. 
	\item Роли пользователей в групповых чатах с различыми правами управления группой.
	\item Поиск сообщений по релевантности и дате.
	\item Просмотр списка участников и их активность (онлайн/оффлайн) в реальном времени.
	\item  Возможность отправлять эмодзи и файлы разных типов.
\end{enumerate}
\subsection{Обоснование выбора технологии проектирования}

Для реализации проектирования интерфейса взаимодействия веб-приложения "Закрытый корпоративный мессенджер" с пользователем были рассмотрены различные подходы и технологии к фронтенд-разработке. Наилучшим стал выбор комбинации языков программирования JavaScript и CSS, а также языка разметки HTML. Этот выбор обусловлен стремлением к достижению максимального контроля над каждым аспектом функциональности, оптимизации производительности и минимизации внешних зависимостей. Такой подход обеспечивает высокую гибкость в процессе разработки, а также эффективность и масштабируемость готового решения. 

\subsection{JavaScript для обеспечения динамического взаимодействия и интерактивности}

Для обеспечения динамического взаимодействия и интерактивности взят нативный JavaScript без использования фреймворков и библиотек. Java-Script файлы (app.js, login.js, register.js) являются "мозгом" клиентской части веб-приложения, обеспечивая всю интерактивность, динамические обновление контента и асинхронное взаимодействие с серверной частью. Одним из важных аспектов выбора данного языка программирования является уникальная способность работать напрямую в браузере. Это позволяет пользователям открывать мессенджер на любом устройстве - смартфон, планшет, ноутбук - без установки дополнительных программ.

\subsubsection {Функциональные возможности, реализованные с помощью JavaScript} 

JavaScript является ключевым элементом, который превращает статические HTML-страницы в динамичное и интерактивное веб-приложение. В данном проекте весь клиентский функционал, от управления пользовательскими сессиями до обработки сообщений в реальном времени и навигации по интерфейсу, реализован с использованием чистого Javascript, без сторонних фреймворков и библиотек. Далее подробно описаны основные интерактивные возможности, реализованные в файлах login.js, register.js и app.js.

\subsubsection {Управление аутентификацией и регистрацией}

Одна из самых главных возможностей является - Управление аутентификацией и регистрацией (login.js, register.js).

Файлы login.js и register.js представляют собой автономные модули, ответственные за логику, связанную с входом и регистрацией пользователей соответственно. Они демонстрируют ключевые принципы нативной JavaScript-разработки: прямое взаимодействие с DOM, асинхронные запросы и управление локальным состоянием без использования фреймворков.

Обработка отправки форм. Скрипты перехватывают событие отправки форм (sumbit) для элементов с id="login-form" и id="register-form". Вместо стандартной отправки страницы, данные из полей ввода "логин" и "пароль" извлекаются и подготавливаются для асинхронной передачи. 

Клиентская валидация данных. До отправки на сервер выполняется проверка их корректности непосредственно в браузере пользователя. Это повышает отзывчивость приложения, так как пользователь получает мгновенную обратную связь без задержек, связанных с сетевым запросом к серверу. Принцип работы:
\begin{enumerate}
	\item Проверка на пустоту. Скрипт проверяет, не являются ли поля username (логин пользователя) и password (пароль пользователя) пустыми.
	\item Если одно из полей пустое, то к соответствующему полю ввода добавляется CSS класс input-error (ошибка ввода). Этот класс изменяет границу поля на красный цвет и фон на светло-красный, визуально сигнализируя пользователю об ошибке.
	\item На пустое поле, функция showToast() вызывается для отображения всплывающего сообщения: "Пожалуйста, заполните это поле".
	\item Выполнение функции прерывается (return), предотвращая отправку некорректных данных на сервер.
	\item Удаление индикации ошибок. При каждом новом событии input (ввода текста в поле) или при попытке повторной отправки формы, ранее добавленный класс input-error удаляется, чтобы очистить визуальную индикацию предыдущих ошибок. Это создает динамичную и понятную обратную связь для пользователя.
\end{enumerate}

Асинхронное взаимодействие с сервером API. После успешной клиентской валидации данные отправляются на сервер без перезагрузки страницы. Это достигается за счет использования современного API fetch(). Принцип работы:

\begin{enumerate}
	\item Создается объект запроса, включающий: URL, метод, заголовки, тело запроса.
	\item URL для входа /login, для регистрации /register.
	\item Метод всегда POST, так как происходит отправка данных.
	\item Заголовки headers, указывается Content-Type: application/json, чтобы сервер знал, что ожидать JSON-данные.
	\item Тело запроса body. Даннные пользователя индикатор (логин, никнейм) и аутентификатор (пароль) конвертируются в JSON-строку с помощью JSON.stringify().
	\item Отправка запроса fetch('/api/login', {...}) или fetch('/api/register', {...}) инициирует сетевой запрос.
	\item Обработка успешного ответа или ошибок. Если response.ok истинно и data.success истинно, это означает успешный вход или регистрацию. Если response.ok ложно или data.success ложно, это указывает на ошибку (например, неверные учетные данные, логин уже занят). В этом случае из data.message извлекается сообщение об ошибке, которое отображается пользователю через showToast().
\end{enumerate}

Для информирования пользователя о результате операций (успех или ошибка) используется функция showToast(). Принцип работы:

\begin{enumerate}
	\item Диначеское создание элементов. Функция showToast(message, type) принимает текст сообщения и его тип success или error.
	\item Она динамически создает новый HTML-элемент div (toastElement), который служит контейнером для уведомления.
	\item К этому элементу добавляются CSS-классы alert, а также alert-success или alert-error в зависимости от типа сообщения. Эти классы, определенные в login.css и register.css, задают внешний вид уведомления: цвет фона, рамки, тени, отступы.
	\item Внутрь toastElement вставляется иконка и текст сообщения.
	\item Размещение в DOM. Созданный toastElement добавляется в специальный контейнер alert-container, который расположен фиксировано в верхней правой части экрана.
	\item Анимация появления и исчезновения.  CSS-класс slideIn, определенный в login.css и register.css череез @keyframes alertSlideIn, обеспечивает плавное появление уведомления сверху.
	\item Через несколько секунд уведомление автоматически удаляется из DOM путем toastElement.remove().
\end{enumerate}

В совокупности, login.js и register.js демонстрируют примеры эффективного и управляемого JavaScript-кода для реализации критически важных функций аутентификации и регистрации в веб-приложении "Закрытый корпоративный мессенджер".

\subsubsection{Основная логика чата и интерактивность}

Основная логика чата и интерактивность реализованна в app.js. Центральным JavaScript файлом является app.js, который управляет всей динамической частью интерфейса мессенджера после успешного входа пользователя (index.html). Он координирует отображение данных, реакцию на действия пользователя и взаимодействие с серверным API. 
При загрузке index.html или при перенаправлении на него после входа, app.js выполняет начальную настройку:

\begin{enumerate}
	\item Проверка аутентификации. Скрипт получает данные о пользователе (username) из sessionStorage. Это критически важно для поддержания состояния входа.
	\item Отображение имени пользователя. После успешной проверки сессии, логин пользователя из sessionStorage динамически вставляется в элемент <span class="username-display" id="username-display"> в заголовке, персонализируя интерфейс. 
	\item Получение ссылок на DOM-элементы. App.js получает ссылки на все ключевые HTML-элементы, с которыми предстоит взаимодействовать: chatBox, messageInput, sendButton, sidebarToggle, membersToggle, различные модальные окна и их кнопки, списки groupsList, privateChatsList, membersList и другие.
\end{enumerate}

Управление боковыми панелями (сайдбарами). Интерфейс мессенджера имеет две выдвижные боковые панели: одну для групп и личных чатов, другую для списка участников. Переключение видимости:
\begin{enumerate}
	\item Кнопки sidebar-toggle для групп и members-toggle для участников в шапке имеют обработчики кликов.
	\item При клике app.js добавляет или удаляет CSS класс .active у соответствующих элементов <aside class="sidebar"> и <aside class="members-sidebar">.
	\item Взаимодействие с CSS. В style.css определены правила, которые используют класс .active для изменения положения сайдбаров. Это в сочетании с CSS свойством transition, создает плавную анимацию выдвижения и скрытия панелей.
	\item Кнопки закрытия sidebar-close и members-close внутри самих сайдбаров также управляют этим классом, позволяя закрыть панель.
\end{enumerate}

Диманическое заполнение списков:
\begin{enumerate}
	\item Группы и личные чаты. Функции loadGroups() и loadPrivateChats() (вызываемые при инициализации или обновлении) отправляют асинхронные fetch() запросы к серверу. Полученные списки групп и личных чатов итерируются, и для каждого создает HTML-элемент. 
	\item Список участников. Функция loadGroupMembers(groupId) вызывается при выборе группового чата. Она запрашивает у сервера список участников этой группы. Стилизация статуса онлайн или офлайн достигается CSS классом .online.
\end{enumerate}

Управление историей чата и отправкой сообщений. Динамическое отображение сообщений, отпрвка нового контента и удобная навигация по истории переписок:
\begin{enumerate}
	\item Выбор чата. При клике на чат в сайдбаре, через selectGroup или selectPrivateChat очищает поле сообщений, устанавливает активный чат и вызывает loadMessages() для загрузки истории. Заголовок чата обновляется.
	\item Загрузка и отображение сообщений. Функция loadMessages() отправляет fetch() запрос к серверу. Полученные сообщения динамически преобразуются в HTML renderMessage, добавляются в chat-box и стилизуются. Автоматически chat-box прокручивается к новым сообщениям.
	\item Отправка сообщений и файлов. Обработчики событий на message-input и send-button извлекают текст и файлы, асихронно отправляют их на сервер fetch(). После отправки сообщение сразу добавляется в chat-box, поле ввода очищается, и chat-box прокручивается вниз. Ошибки отображаются через showToast().
	\item Бесконечная прокрутка. Событие scroll на chat-box определяет прокрутку к верху. Если достигнут верх, app.js вызывает loadMoreMessages(), запрашивая у сервера предыдущую порцию сообщений для подгрузки истории.
\end{enumerate}

Управление модальными окнами. Контролирует отображение и функциональность различных модальных окон, накладывающихся на основной интерфейс:
\begin{enumerate}
	\item Открытие и закрытие. При клике на соответствующие кнопки, app.js добавляет или удаляет CSS класс .active к элементу модального окна .custom-modal, что делает его видимым или скрытым с помощью стилей. Кнопки закрытия .close-modal и отмены cancel кнопки также управляют этим классом.
	\item Создание групп create-group-modal. Обрабатывается ввод имени группы, отправка на сервер и обновление списка групп после успешного создания.
	\item Добавление участников add-member-modal позволяет добавить пользователя в активную группу, обновляя список участников.
	\item Поиск сообщений search-modal. Обрабатывает поисковые запросы, отправляет их на сервер и отображает результаты.
	\item Подтверждение действий confirmation-modal. Универсальное окно, где app.js динамически устанавливает заголовок и сообщение. Кнопки "Подтвердить" и "Отмена" выполняют или отменяют соответствующие действия. 
	\item Переименование группы rename-group-modal. Позволяет изменить название активной группы через запрос на сервер и обновление UI.
\end{enumerate}

Управление пользователями и группами:
\begin{enumerate}
	\item Контекстное меню участника. При правом клике на участнике в списке member-list, app.js динамически отображает контекстное меню member-context-menu с опциями "Изменить роль" или "Удалить из группы".
	\item Изменение ролей и удаление. При выборе опции из контекстного меню, JavaScript отправляет соответствующие запросы на сервер /api/change-role, /api/remove-member. После успешного выполнения, список участников обновляется.
	\item Выход из группы и удаление группы. Через кнопки или контекстное меню, app.js инициирует запросы на сервер для выхода из группы или удаления группы (для администратора и создателя группы), используя модальное окно подтверждения. 
\end{enumerate}

Обратная связь пользователю. Всплывающие уведомления showToast(). Эта функция (определенная в login.js и register.js и доступная глобально или импортируемая в app.js) используется для отображения кратких сообщений alerts-container об успешных операциях. Уведомление появляются и исчезают с помощью CSS анимаций slideIn.

Управление сессией. Функция выхода logout(). Определена непосредственно в index.html и вызывается, например, кнопкой "Выйти". Она очищает все данные сессии из sessionStorage и удаляет соответствующие куки document.cookie, а затем  перенаправляет пользователя на login.html, завершая сессию.

Таким образом, app.js является сложным и многофункциональным скриптом, который связывает HTML структуру с CSS стилями и серверным API, создавая полноценное и интерактивное клиентское приложение мессенджера.

\subsection{Реализованный дизайн и стилизация при помощи CSS}

CSS в этом проекте используется для создания привлекательного, функционального и адаптивного пользовательского интерфейса, обеспечивая единообразие дизайна и удобство использования на различных устройствах. Файлы style.css, login.css, register.css, error.css играют ключевую роль в визуальном оформлении, компоновке и адаптивности всего пользовательского интерфейса.

\subsubsection{Общая стилизация и брендинг}

Для определения общей эстетики и визуальной идентичности приложения, включая цвета, шрифты и единообразные стили элементов:
\begin{enumerate}
	\item Глобальные переменные. В корневом элементе (:root)
	файла style.css определены CSS переменные (--primary, --secondary, --text, --accent). Это позволяет легко управлять основной цветовой палитрой и использовать эти цвета по всему проекту, обеспечивая консистентность и упрощая будущие изменения дизайна.
	\item Типографика. Установлен основной шрифт font-family: Arial, sans-serif в style.css, Segoe UI, system-ui... в login.css и register.css, размер шрифтов и цвет текста для различных элементов, что создает читаемый и приятый внеший вид.
	\item Фоновые стили. Для страниц входа и регистрации используются красивые градиенты background: linear-gradient, придающие им современный вид. Основая страница style.css имеет более нейтральный фон. 
	\item Единый стиль элементов. Применены общие стили для кнопок, полей ввода, контейнеров (border-radius: 15px, box-shadow), что создает визуально связный дизайн.
\end{enumerate}

\subsubsection{Макет и компоновка элементов}

Раздел описывает, как CSS отвечает за расположение всех компонентов на странице, создавая функциональную и интуитивно понятную структуру пользовательского интерфейса.

\begin{enumerate}
	\item Flexbox для гибкой компоновки. Широко используется display: flex для создания гибких контейнеров, позволяющих легко выравнивать элементы и распределять пространство. Например, body на всех страницах использует display: flex для центрирования содержимого или организации элементов в колонки. В chat-container и sidebar-content также используется flex-direction: column для вертикального размещения элементов.
	\item Основной макет страницы. Элемент chat-container на index.html имеет фиксированную ширину на больших экранах width: 1200px и центрируется по горизонтали margin: 80px auto 20px. Он имеет тень box-shadow и скругленные углы, выделяя его как основной элемент интерфейса.
	\item Элемент chat-box внутри chat-container занимает большую часть вертикального пространства height: 70vh; flex-grow: 1 и настроен на прокрутку по вертикали overflow-y: auto.
	\item Позиционирование сайдбаров. Боковые панели .sidebar, members-sidebar позиционированы фиксировано position: fixed з пределами видимой области экрана.
	\item Свойство transition используется для плавного перемещения сайдбаров при добавлении и удалении класса .active.
	\item Стилизация форм. Контейнеры форм на страницах входа и регистрации .container имеют приятные тени box-shadow, скругленные углы и центрированы. Поля ввода input-container, input имеют современный вид с отступами и иконками-заполнителями. 
\end{enumerate}

\subsubsection{Адаптивный дизайн}
Корректное и удобное отображение интерфейса мессенджера на широком спектре устройств и размеров экранов. Медиазапросы @media в style.css, login.css, register.css активно используют медиазапросы с брейкпоинтами --mobile-breakpoint: 768px и --phone-breakpoint: 480px. Это позволяет адаптировать макет и стили под различные размеры экранов:
\begin{enumerate}
	\item На мобильных устройствах max-width: 768px или 480px chat-container становится полноразмерным width: auto; margin: 0, боковые панели скрываются по умолчанию (чтобы не занимать много месте), а кнопки управления ими становятся более компактными.
	\item Элементы форм и текст могут изменять свой размер, чтобы быть более читаемыми на маленьких экранах.
	\item Позиционирование уведомлений alerts-container также адаптируется для мобильных устройств.
	\item Гибкие размеры. Использование относительных единиц измерения (например, vh, vw, rem) и flex-grow обеспечивает, что элементы будут масштабироваться пропорционально размеру экрана.
\end{enumerate}

\subsubsection{Интерактивные и визуальные эффекты}
Для придания динамичности и отзывчивости элементам интерфейса, улучшая взаимодействие пользователя с приложением:
\begin{enumerate}
	\item Эффекты наведения (hover effects). Кнопки и интерактивные элементы имеют :hover состояния, которые изменяют их внешний вид (цвет фона, тень) давая пользователю обратную связь. 
	\item Анимация "сияния" на кнопках. В login.css и register.css определена анимация @keyframes shine, которая с помощью псевдоэлемента ::after создает эффект "бегущего света" по кнопкам при наведении курсора, делая их более динамичными.
	\item Анимация появления уведомлений. Для всплывающих уведомлений .alert используется @keyframes alertSlideIn и animation: slideIn 0.3s ease-out, что обеспечивает их плавное появление сверху.
	\item Стилизация сообщений. Классы .my-message и .other-message имеют различные стили (background-color, align-self) для четкого разделения сообщений, отправленных текущим пользователем, от сообщений других участников. 
	\item Состояние ошибок. Класс .input-error стилизует поля ввода с ошибками (красная рамка, светло-красный фон), мгновенно сообщая пользователю о некорректном вводе.
	\item Модальные окна. Стили для .custom-modal и .modal-content обеспечивают их центрирование, затемнение фона под ними и плавное появление.
\end{enumerate}

В целом, CSS в этом приложении является мощным инструментом, который не только определяет внешний вид каждого элемента, но и создает удобный, динамичный и адаптивный пользовательский опыт. 

\subsection{Реализованная структура и содержимое при помощи HTML}
HTML (HyperText Markup Language) является основой каждой страницы веб-приложения "Закрытый корпоративный мессенджер", определяя её скелет, логическую структуру и размещение всех элементов пользовательского интерфейса. В мессенджере HTML используется для создания следующих ключевых компонентов.

\subsubsection{Структура страниц аутентификации}
Страницы login.html и register.html обеспечивают начальный вход пользователя в систему и создание аккаунта. На этих страницах реализованы следующие функции:
\begin{enumerate}
	\item Основной контейнер .container. Центральный блок, содержащий всю форму входа или регистрации. Он имеет стили, которые делают его визуально привлекательным и заметным. 
	\item Формы (<form>). Для страницы входа id="login-form",  для регистрации id="register-form".
	\item Обе формы содержат заголовок, поля ввода, кнопка отправки, ссылки для навигации.
	\item Заголовок <h2> информирует польователя о назначении формы ("Приветствую!" или "Регистрация аккаунта").
	\item Поля ввода <input type="text" id="username">, <input type="password" id="password"> для ввода имени пользователя и пароля. Они имеют placeholder для подсказок и autocomplete="off" для удоства и безопасности. 
	\item Кнопка отправки <button type="sumbit"> активирует процесс входа или регистрации.
	\item Ссылки для навигации позволяют пользователю переключаться между страницами входа и регистрации <a href="register.html" или <a href="login.html">.
	\item Контейнер для уведомлений <div id="alerts-container">. Пустой div, предназначенный для динамического отображения всплывающих сообщений об успехе или ошибках, управляемых JavaScript и стилизованных CSS. 
\end{enumerate}

\subsubsection{Структура основной страницы мессенджера}
Страница index.html является центральным интерфейсом для взаимодействия с чатом. 
Шапка header:
\begin{enumerate}
	\item Контейнер кнопок .header-buttons-container группирует элементы управления в верхней части экрана.
	\item Кнопка для открытия и закрытия левой боковой панели списка групп sidebar-toggle.
	\item Кнопка для открытия и закрытия правой боковой панели списка участников чата members-toggle.
	\item Место, где будет динамически отображаться никнейм текущего пользователя <span class="username-display" id="username-display".
	\item Место для кнопки выхода .logout-btn.
\end{enumerate}
Боковые панели (сайдбары) состоит из левой и правой панели. Левая панель <aside class="sidebar">:
\begin{itemize}
	\item заголовок <h3 class="sidebar-title">Мои группы</h3>;
	\item кнопка закрытия sidebar-close;
	\item контейнеры для списков чатов для групповых чатов и личных.
\end{itemize}
Правая панель <aside class="members-sidebar">:
\begin{itemize}
	\item заголовок <h3 class="sidebar-title">Участники</h3>;
	\item кнопка закрытия members-close;
	\item список участников <ul id="members-list"> динамически заполняется списком участников активной группы.
\end{itemize}
Основная область чата <div class="chat-container">:
\begin{enumerate}
	\item Главная область, где динамически отображается вся история переписки окно для сообщений <div class="chat-box">. Этот блок настроен на прокрутку, что позволяет просматривать большое количество сообщений.
	\item Панель ввода сообщений <div class="message-input-area">.
	\item Поле ввода текста <textarea id="message-input"> для набора сообщений.
	\item Кнопка отправки <button id="send-button"> для отправки набранного текста.
	\item Поле для прикрепления файлов <input type="file" id="file-input"> позволяет пользователю выбирать файлы для отправки. 
\end{enumerate}
Модальные окна .custom-modal. HTML включает скрытые по умолчанию display: none в CSS структуры для различных модальных окон. Они становятся видимыми и взаимодействуют с пользователем при активации. Примеры включают:
\begin{itemize}
	\item для создания новой группы create-group-modal;
	\item для добавления участников группу add-member-modal;
	\item для поиска сообщений в чате search-modal;
	\item универсальное окно для подтверждения различных действий (выход из группы, удаление пользователя) confirmation-modal;
	\item для переименования группы rename-group-modal.
\end{itemize}
Все модальные окна имеют общую структуру: внешний div.custom-modal, внутренний div.modal-content, кнопку закрытия .close-modal и набор кнопок действий .modal-buttons.
Таким образом, HTML обеспечивает полную и логически структурированную основу для всех визуальных и функциональных компонентов мессенджера, которые затем оживают благодаря CSS и JavaScript.
