\section{Технический проект}
\subsection{Общая характеристика организации решения задачи}

Необходимо разработать концепцию пользовательского интерфейса для закрытого корпоративного мессенджера, который будет спроектирован как единое, адаптивное, кроссплатформенное веб-приложение, обеспечивающий комфортную работу на различных устройствах (компьютеры, планшеты, мобильные телефоны). В его основе лежит четкая структура и логика, призванная упростить доступ к ключевым функциям.

\begin{enumerate}
	\item Регистрация и авторизация пользователя путем идентификатора (логин) и аутентификатора (пароль) на страницах register и login.
	\item Возможность создавать групповые чаты.
	\item Возможность вести личный чат с другими пользователями. 
	\item Роли пользователей в групповых чатах с различыми правами управления группой.
	\item Поиск сообщений по релевантности и дате.
	\item Просмотр списка участников и их активность (онлайн/оффлайн) в реальном времени.
	\item  Возможность отправлять эмодзи и файлы разных типов.
\end{enumerate}
\subsection{Обоснование выбора технологии проектирования}

Для реализации проектирования интерфейса взаимодействия веб-приложения "Закрытый корпоративный мессенджер" с пользователем были рассмотрены различные подходы и технологии к фронтенд-разработке. Наилучшим стал выбор комбинации языков программирования JavaScript и CSS, а также языка разметки HTML. Этот выбор обусловлен стремлением к достижению максимального контроля над каждым аспектом функциональности, оптимизации производительности и минимизации внешних зависимостей. Такой подход обеспечивает высокую гибкость в процессе разработки, а также эффективность и масштабируемость готового решения. 

\subsubsection{JavaScript для обеспечения динамического взаимодействия и интерактивности}

Для обеспечения динамического взаимодействия и интерактивности взят нативный JavaScript без использования фреймворков и библиотек. Java-Script файлы (app.js, login.js, register.js) являются "мозгом" клиентской части веб-приложения, обеспечивая всю интерактивность, динамические обновление контента и асинхронное взаимодействие с серверной частью. Одним из важных аспектов выбора данного языка программирования является уникальная способность работать напрямую в браузере. Это позволяет пользователям открывать мессенджер на любом устройстве - смартфон, планшет, ноутбук - без установки дополнительных программ.

\subsubsection{Реализованный дизайн и стилизация при помощи CSS}

CSS в этом проекте используется для создания привлекательного, функционального и адаптивного пользовательского интерфейса, обеспечивая единообразие дизайна и удобство использования на различных устройствах. Файлы style.css, login.css, register.css, error.css играют ключевую роль в визуальном оформлении, компоновке и адаптивности всего пользовательского интерфейса.


\subsubsection{Реализованная структура и содержимое при помощи HTML}
HTML (HyperText Markup Language) является основой каждой страницы веб-приложения "Закрытый корпоративный мессенджер", определяя её скелет, логическую структуру и размещение всех элементов пользовательского интерфейса.

Диаграмма компонентов иллюстрирует архитектуру клиентской части корпоративного мессенджера. Система организована в виде набора взаимосвязанных компонентов, каждый из которых отвечает за определенный аспект функциональности.

\subsubsection{Main Page}
Главная страница (Main Page) служит центральным узлом мессенджера, где пользователь взаимодействует со всеми основными функциями. Она объединяет четыре ключевых компонента: 
\begin{enumerate}
	\item Шапку (Header) в верхней части экрана, обеспечивающую быстрый доступ к управлению группами и аутентификацией.
	\item Боковую панель (Sidebar), которая скрывается при малом разрешении экрана и содержит интерактивные списки групповых и личных чатов с возможностью динамического поиска пользователей.
	\item Центральную область чата (Chat Area), где в реальном времени отображаются сообщения с поддержкой форматирования, вложений и контекстного меню для управления.
	\item Форму отправки (Message Form) с автоподстройкой высоты текстового поля, кнопками для вставки эмодзи и прикрепления файлов.
\end{enumerate}

Страница управляется скриптом App Controller. Он инициализирует компоненты при загрузке DOM, обрабатывает пользовательские события, синхронизирует состояние интерфейса с sessionStorage, координирует обмен данными с сервером и обеспечивает мгновенную обратную связь. Для единообразия интерфейса используются централизованные стили (Styles), адаптирующие макет под мобильные устройства и десктопы через медиазапросы.

Ключевые функции включают: 
\begin {itemize}
	\item переключение между общим чатом, групповыми и личными диалогами с сохранением состояни;
	\item "Бесконечную" ленту сообщений с автоподгрузкой истории; 
	\item систему уведомлений через тосты и звуковые сигналы; 
	\item контекстно-зависимые действия (редактирование/удаление сообщений, просмотр вложений). 
\end{itemize}

Визуальная идентичность выдержана в мягкой розово-персиковой гамме с плавными анимациями открытия меню, появления сообщений и hover-эффектами кнопок, создающими интуитивно понятный UX.
\subsubsection{Register Page}
Эта страница схожа по дизайну с login, но с усиленной логикой валидации. Здесь форма регистрации не только проверяет длину и допустимые символы логина (блокируя спецсимволы кроме дефисов и подчёркиваний), но и асинхронно сверяется с сервером на уникальность имени через фоновые запросы. Особое внимание уделено безопасности: пароли никогда не отображаются открыто, а при отправке шифруются перед передачей на /register. Интерактивная обратная связь включает многоуровневые подсказки – например, подсветку поля пароля при недостаточной длине с анимацией "тряски", иконки успеха или ошибки в реальном времени. 
\subsubsection{Login Page}
Страница входа служит шлюзом для существующих пользователей, предлагая интуитивный интерфейс аутентификации. Центральным элементом является компактная форма с плавными градиентными фонами, выполненная в единой персиково-розовой гамме с главным интерфейсом. Пользователь встречает два интерактивных поля: для ввода имени (требует 3-15 символов, поддерживает кириллицу/латиницу) и пароля (минимум 6 символов), где каждое поле динамически реагирует на действия: текст плавно сдвигается при фокусе, а невалидные значения подсвечиваются красной подсветкой. При нажатии на кнопку "Войти" происходит асинхронная проверка данных через POST-запрос к эндпоинту /login – система шифрует пароль, обрабатывает возможные ошибки  через toast-уведомления с иконками состояния, а при успехе сохраняет session id в хранилище браузера и мгновенно перенаправляет в главный чат. Дополнительно реализована ссылка для новых пользователей – "Зарегистрироваться" с hover-эффектом, ведущая на соответствующую страницу.
\subsubsection{Header}
Шапка является навигационной панелью, постоянно закрепленной в верхней части экрана. Её реализация сочетает динамическую адаптацию под состояние пользователя и управление ключевыми элементами интерфейса. При загрузке страницы функция updateAuthButtons() проверяет наличие username в sessionStorage, мгновенно реконфигурируя содержимое: для авторизованных пользователей отображается персональное приветствие ("Вы вошли: username") с оформленной кнопкой выхода, выполненной в розовой гамме с плавной анимацией при наведении; для неавторизованных пользователей – лаконичные кнопки "Регистрация" и "Вход" с иконками-индикаторами. 
Центральную функциональную зону занимают кнопки управления боковыми панелями: "Группы" активирует левый сайдбар со списком чатов через добавление класса .active, что инициирует CSS-анимацию плавного выезда, а "Участники" аналогично контролирует правую панель с участниками текущего чата. Обе кнопки оснащены продвинутой обработкой событий – при клике срабатывает e.stopPropagation() для предотвращения всплытия, а на мобильных устройствах (media-query 480px) они трансформируются в компактные иконки без текста.

Технически компонент построен на flex-контейнере с продуманным z-index (1000), гарантирующим поверхностное расположение над контентом. Фон реализован как полупрозрачное покрытие (rgba(255,255,255,0.9)) с эффектом размытия (backdrop-filter: blur(6px)), создающим "стеклянную" текстуру. В адаптивном режиме происходит перераспределение элементов: имя пользователя ужимается до 40 процентов ширины с многоточием при переполнении, а кнопки аутентификации минимизируются до иконок с сохранением функциональности.
\subsubsection{Message Form}
Форма сообщений служит интеллектуальным инструментом для создания и отправки контента, органично встроенным в нижнюю часть чат-интерфейса. Её ядром является адаптивное текстовое поле, которое динамически расширяется по вертикали при вводе – от минимальной высоты в одну строку до максимальных шести строк, что достигается комбинацией JavaScript-расчета scrollHeight и CSS-свойств transition. Пользователь взаимодействует с формой через три стратегических элемента: кнопку отправки (стилизованную под стрелку), эмодзи-пикер с сеткой из 60+ смайлов, появляющийся при клике на иконку улыбки, и файловый инпут, активируемый скрепкой.

Отправка сообщения инициируется либо нажатием кнопки, либо комбинацией Enter (без Shift), что блокирует стандартный перенос строки через e.preventDefault(). Для работы с файлами реализован продвинутый менеджер вложений: при выборе изображений или документов появляются превью (миниатюры для картинок, иконки для файлов), счетчик количества и кнопка сброса. Алгоритм автоматически фильтрует дубликаты по имени и размеру, а также применяет ограничения.

Технически отправка данных использует гибридный подход: текст и файлы упаковываются в FormData с автодобавлением контекста (ID группы или получателя для личных чатов). Для приватных сообщений включается AES-шифрование через CryptoJS с сессионным ключом из sessionStorage. Визуальная обратная связь реализована через временные полупрозрачные сообщения-заглушки с пометкой "temp", которые исчезают после подтверждения сервера. При ошибках сетевого взаимодействия система демонстрирует анимированные toast-уведомления с детализацией проблемы, а при попытке отправить пустое сообщение – запускает микроанимацию "вибрации" поля ввода.

Дизайн формы выдержан в общей стилистике с плавными градиентами, скругленными углами (12px) и интерактивными тенями при наведении. На мобильных устройствах происходит трансформация: элементы перестраиваются в вертикальную компоновку с увеличенными touch-зонами, а кнопки снабжаются текстовыми подписями для улучшения юзабилити. Интеграция с глобальным AppController обеспечивает синхронизацию с историей сообщений и мгновенное обновление списка чатов после успешной отправки, создавая бесшовный пользовательский опыт.

\subsubsection{Chat Area}
Область чата служит динамическим ядром интерфейса, где в реальном времени отображаются все сообщения через систему рендеринга. Её пространство организовано как вертикальный ленточный контейнер с автоматической прокруткой к новым сообщениям, где каждое сообщение оформляется в соответствии с типом: 
\begin{itemize}
	\item пользовательские блоки содержат имя отправителя, временную метку в формате HH:MM, текстовое содержимое и визуализацию вложений;
	\item системные уведомления центрируются и выделяются серой цветовой гаммой с курсивным начертанием; 
	\item временные сообщения-заглушки отображаются с полупрозрачностью во время обработки данных.
\end{itemize}

Технологически рендеринг управляется функцией displayMessages(), которая обрабатывает поступающие данные через сложный алгоритм сортировки по временным меткам, фильтрации дубликатов и интеллектуального позиционирования. Система автоматически определяет принадлежность сообщений текущему пользователю – его сообщения визуально выделяются смещением вправо и уникальным градиентным фоном, создавая интуитивное различие. Для работы с мультимедиа реализованы специализированные блоки: изображения отображаются адаптивными миниатюрами с возможностью просмотра в модальном окне при клике, а файлы сопровождаются иконками типа документа и прямой ссылкой для скачивания.

Ключевой особенностью является контекстное меню, активируемое долгим нажатием или правым кликом, которое предлагает расширенный набор действий:
\begin{itemize}
	\item редактирование текстовых сообщений (с подсветкой изменений);
	\item удаление с подтверждением через модальное окно;
	\item просмотр вложений в полноэкранном режиме и массовое скачивание файлов. 
\end{itemize}
	
Для обеспечения производительности реализована виртуализация контента – загружаются только сообщения, попадающие в видимую область, с динамической подгрузкой истории при прокрутке вверх.

Анимационная система включает несколько уровней: 
\begin{itemize}
	\item плавное появление новых сообщений с эффектом сдвига слева;
	\item подсветка измененных текстов пульсирующим желтым фоном;
	\item визуальные индикаторы загрузки файлов. 
\end{itemize}

При взаимодействии реализованы тактильные отклики на мобильных устройствах через CSS-трансформации. Техническая интеграция включает синхронизацию с AppController для мгновенного отображения отправленных сообщений и систему проверки удаленного контента – при обнаружении удаленных на сервере сообщений они автоматически исчезают из ленты.

Адаптивный дизайн перестраивает область чата на малых экранах: уменьшает боковые отступы сообщений, заменяет горизонтальные превью файлов на вертикальные стопки, и активирует компактный режим временных меток. Фоновый процесс checkForUpdates() каждые 5 секунд проверяет новые сообщения через API, обеспечивая живую ленту без ручного обновления, а шифрование личной переписки реализовано через AES-алгоритмы библиотеки CryptoJS с ключами сессии.
\subsubsection{App Controller}
App Controller выступает центральным "мозгом" клиентской части приложения, координирующим все процессы и синхронизирующим компоненты в единую экосистему. Его архитектура построена вокруг системы событийных слушателей, инициализируемых при загрузке DOM (DOMContentLoaded), которые превращают статичный интерфейс в динамическую рабочую среду. Контроллер управляет жизненным циклом данных: от восстановления состояния чата из sessionStorage (последняя активная группа или личный диалог) до обработки реального времени через WebSocket-подобный механизм длинных опросов, где функция checkForUpdates каждые 5 секунд запрашивает сервер на наличие новых сообщений, изменений в группах и статусах пользователей.

Ключевая ответственность включает сложную маршрутизацию действий: 
\begin{itemize}
	\item при выборе группового чата контроллер последовательно проверяет права доступа через /check group access;
	\item загружает историю сообщений и участников;
	\item обновляя одновременно три независимых компонента (список групп, область сообщений, панель участников). 
\end{itemize}	
Для личных чатов дополнительно активируется механизм сквозного шифрования – сообщения дешифруются библиотекой CryptoJS с использованием ключа сессии из sessionStorage перед отображением. Система ошибок обрабатывается по многоуровневому принципу.

Визуальные взаимодействия усилены анимационными конвейерами: плавное появление системных уведомлений через keyframe-анимацию slideIn, highlight-эффекты для новых сообщений с постепенным затуханием, тактильная отдача при ошибках ввода через CSS-трансформации. Для мобильных устройств реализованы специализированные обработчики – долгое нажатие активирует контекстное меню вместо hover, а клавиатурные события автоматически регулируют высоту формы ввода. Технической особенностью является каскадная инициализация модулей: сначала настраиваются слушатели событий, затем загружаются данные чатов, после чего активируется фоновая синхронизация – это гарантирует стабильную работу даже при медленном соединении.

\subsubsection{Styles}
Стили представляют собой унифицированную систему дизайна, пронизывающую все компоненты приложения через централизованный CSS-файл с продуманной архитектурой. Основой служит система кастомных свойств (CSS Variables), задающая фирменную цветовую палитру: персиковые и розовые оттенки для акцентов, контрастирующие с глубокими текстовыми тонами и нейтральным фоном. Система реализует адаптивный дизайн через три ключевых контрольных точки (1200px, 768px, 480px), где макеты плавно трансформируются – на мобильных устройствах горизонтальные панели перестраиваются в вертикальные стеки, touch-элементы увеличиваются до 48px, а сложные компоненты переходят в полноэкранный режим с выезжающей анимацией.

\subsubsection{Chat Manager}

Менеджер чата функционирует как высокооптимизированный двигатель обработки сообщений, управляющий жизненным циклом контента от получения до визуализации. Его ядром является многоуровневая система загрузки данных, которая интеллектуально разделяет три типа чатов: общий (через /get messages), групповой (через /get group messages?group id=) и личный (через /get private messages?user=) с автоматическим переключением логики. При инициализации чата менеджер восстанавливает последнюю позицию прокрутки и временную метку последнего сообщения из sessionStorage, формируя запросы с параметром lastTimestamp для подгрузки. Для личных чатов активируется дополнительный слой криптографии: полученные сообщения дешифруются через AES-алгоритм CryptoJS с использованием ключа сессии из sessionStorage, при этом процесс полностью скрыт от пользователя.

Отправка сообщений реализуется через гибридный подход: текстовые данные и файлы упаковываются в FormData, а для личных чатов текст предварительно шифруется тем же ключом. Перед отправкой создается временное локальное сообщение-заглушка с уникальным ID, которое визуально сигнализирует о процессе и заменяется финальным сообщением после подтверждения сервера.

Сложные алгоритмы обеспечивают целостность данных: функция checkDeletedMessages периодически сверяет локальные сообщения с сервером и удаляет отсутствующие, а checkEditedMessages отслеживает правки через хеш-суммы контента, автоматически обновляя текст в интерфейсе с пульсирующей подсветкой изменений. Для работы с вложениями реализован адаптивный препроцессинг: изображения сжимаются до 200px по ширине с сохранением пропорций, а файлы группируются по типу с иконками-индикаторами. 

Система ошибок включает многоступенчатое восстановление: при сетевых сбоях автоматически повторяет отправку с экспоненциальной задержкой, при ошибке 403 (отказано в доступе к группе) сбрасывает текущий чат и перенаправляет в общий чат, а при обнаружении несоответствия ключей шифрования инициирует повторную аутентификацию. Адаптивная синхронизация с интерфейсом осуществляется через центральный объект UI, что позволяет менеджеру динамически обновлять списки чатов при отправке нового сообщения, пересчитывать счетчики непрочитанных и поддерживать актуальность данных в режиме реального времени без перезагрузки страницы.
